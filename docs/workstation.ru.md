# Workstation

Workstation — терминальный интерфейс администратора. Он подключается к Linux-контроллеру через SSH и использует его бэкенд для управления нодами, профилями и настройками.

## Установка и запуск

Используйте [команды установки из README](../README.ru.md#установка-workstation), затем выполните:

```sh
node-plane
```

Минимальный размер терминала — **70 столбцов × 30 строк**. Для таблиц и длинных форм удобнее большее окно. Для отдельного каталога локальных данных:

```sh
node-plane --state-dir /path/to/workstation-data
```

В Windows установщик добавляет **Node Plane Workstation** в меню «Пуск». Найдите приложение через поиск Windows, чтобы открыть его в терминале. Обновление сохраняет ярлык; удаление Workstation удаляет его.

## Подключение к контроллеру

Создайте профиль установки: название, хост/IP, SSH-порт и пользователь. При первом подключении сверьте показанный отпечаток ключа хоста с доверенным источником. Введите SSH-пароль или используйте доступ по ключу.

При установке Workstation регистрирует свой публичный ключ. При подключении к существующему контроллеру ключ связывается с аккаунтом администратора. Если предложено несколько аккаунтов, выберите нужный. Локальные профили установок описывают подключения; VPN-профили описывают доступ пользователей.

Вверху показаны состояние подключения и загрузка. SSH-сессии используются повторно и закрываются после бездействия. Удаление профиля установки удаляет локальное подключение и соответствующую запись ключа хоста; Node Plane на сервере остаётся.

## Навигация

- **↑ / ↓ / ← / →** перемещают фокус; **Enter** активирует выбранный элемент.
- **Tab / Shift+Tab** переключают фокус. Наведение мыши меняет фокус, нажатие активирует элемент.
- Колесо мыши прокручивает длинные страницы. Для перемещения по странице также доступен ползунок.
- **Back** возвращает в родительское меню. **Esc** выходит из подменю или закрывает раздел; на пустом рабочем экране открывает подтверждение выхода.
- В селекторе профиля сайдбара **← / →** переключают установку, оставляя фокус на названии.
- **×** отмечает недоступное действие. Разделы контроллера доступны после подтверждения установки.

## Диагностика установки

Diagnostic сначала проверяет контроллер по SSH: службы, PostgreSQL и контрольные суммы опубликованной схемы. Когда backend доступен, серверы проверяются небольшими группами: агенты, контейнеры и структура конфигов выбранных протоколов, версии и ресурсы хостов. Результаты всех страниц попадают в итоговый прокручиваемый отчёт. Отсутствующий или неполный охват серверов отмечается предупреждением; успешная проверка только контроллера не подтверждает всю установку. Восстановление остановленной службы контроллера требует отдельного подтверждения.

Параметр **Offer service and operation recovery** сохраняет последний выбор между запусками Workstation. Каждое действие восстановления требует своего подтверждения.

## Разделы

| Раздел | Назначение |
| --- | --- |
| Install Node Plane / Node Plane Settings | Установка контроллера; значения по умолчанию, политики, мониторинг, бэкапы, сброс и удаление |
| Node Plane Updates | Релизы, ветки, обновление компонентов и результаты |
| Nodes | Поиск по названию/региону/коду, создание ноды, установка, настройки и диагностика |
| Access | Профили пользователей, запросы, правила доступа и устройства |
| Temporary configs | Создание, получение и отзыв временных конфигов |
| Diagnostic | Службы и схема контроллера, все зарегистрированные серверы и восстановление операций |
| Settings | Локальные профили установок, оформление, обновление Workstation, подключения и сведения о сессии |

При запуске правая часть остаётся пустой до выбора раздела. Если состояние установки не подтверждено, используйте **Check installation**.

Параметры автопроверок, бэкапов и алертов появляются при включении соответствующей функции. Интервал выбирается отдельной кнопкой; для бэкапов также задаётся число сохраняемых копий. **Node Plane Settings → Basic** содержит параметры установки по умолчанию и общие настройки контроллера.

## Установка контроллера

Откройте **Install Node Plane**, заполните поля подключения и установки, проверьте запрос и продолжите. На экране прогресса показаны текущий шаг и путь к журналу. После завершения создайте ноду в **Nodes** и запустите **Server setup**. Следующие действия описаны в [Нодах](nodes.ru.md) и [Доступе](access.ru.md).

## Удаление контроллера

Откройте **Node Plane Settings → Reset & removal**, выберите, нужно ли также удалить ноды, и введите фразу подтверждения. Прогресс обновляется автоматически. Во время подготовки в Node Plane Settings остаются **Finish removal** и **Cancel removal**; завершение становится доступно после удаления нод. Отмена сохраняет контроллер и останавливает дальнейшую подготовку после текущего шага. Уже удалённые ноды она не восстанавливает. После подтверждения **Finish removal** Workstation проверяет удаление и показывает прощальный экран; отмена больше недоступна.

## Оформление и локальные файлы

Workstation хранит подключения, SSH-данные, журналы и темы в каталоге локальных данных ОС внутри `node-plane` или в каталоге из `--state-dir`. Храните его приватно.

В **Settings → Appearance** можно выбрать тему или собственный акцент. Встроенные темы создаются в `themes/`, существующие файлы не перезаписываются. Для своей темы добавьте туда JSON-файл и перезапустите Workstation:

```json
{
  "name": "My theme",
  "accent": "#55b1c2"
}
```

Необязательное поле `section_border` задаёт цвет декоративных рамок отдельно от акцента. Используйте короткое название и цвета `#RRGGBB`. Некорректные темы пропускаются с предупреждением.

## Обновление Workstation

Откройте **Settings → Workstation updates** для обновления приложения на компьютере. **Node Plane Updates** обновляет серверную установку.

Workstation проверяет обновления при запуске и предлагает доступную версию после завершения проверки подключения. Можно отказаться и позже вернуться в **Settings → Workstation updates**.

После успешного обновления приложения нажмите **Restart**, чтобы запустить обновлённую Workstation. Остальные действия недоступны до перезапуска.

Для конфигов используйте **Copy URI** или **Save files**, когда эти действия доступны. В Telegram также доступен QR. См. [Временные конфиги](temporary-configs.ru.md) и [Устранение неполадок](troubleshooting.ru.md).
