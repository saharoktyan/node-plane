# Устранение неполадок

Начните с ошибки операции и её диагностики. Запишите версию, ноду и ID операции. Перед отправкой вывода удалите токены, приватные ключи, DSN и содержимое конфигов.

## Контроллер или бот недоступен

На контроллере:

```sh
cd /opt/node-plane/current
./scripts/healthcheck.sh --mode simple
sudo journalctl -u node-plane-backend -u node-plane-telegram -u node-plane-driver --since '10 minutes ago' -n 150 --no-pager
sudo journalctl -u node-plane-backend-worker --since '10 minutes ago' -n 150 --no-pager
```

Проверьте доступность БД и состояние службы worker. После очистки чата отправьте `/start` снова. Один токен должен опрашивать только один процесс бота.

## Workstation не подключается

Проверьте хост, SSH-порт, пользователя и сеть. Перед принятием нового ключа сверьте отпечаток. Изменённый ключ может означать переустановленный или другой хост; подтвердите это отдельно.

При `permission_denied` / HTTP 403 проверьте роль администратора, доступность аккаунта и привязку ключа Workstation. Root SSH-доступ и разрешения бэкенда проверяются отдельно. Изучите аудит и журналы; не привязывайте один ключ к случайным аккаунтам повторно.

При неподтверждённой установке используйте **Check installation**. Обновления самого Workstation проверяются отдельно от контроллера.

## Агент недоступен или установка заблокирована

На затронутой ноде:

```sh
sudo systemctl status node-plane-agent --no-pager
sudo journalctl -u node-plane-agent --since '10 minutes ago' -n 150 --no-pager
```

Проверьте адрес агента, доступность с контроллера и mutual TLS. Служба running может ещё запускаться. Изучите фазу установки и используйте предложенное восстановление после исправления подключения.

## Runtime установлен, но подключение не работает

Проверьте состояние ноды, публичный DNS/IP и нужные TCP/UDP-порты. У клиента должен быть актуальный конфиг и поддержка протокола. Для одновременных AWG-клиентов используйте разные устройства.

```sh
sudo docker ps -a
```

Не публикуйте полные настройки контейнеров и VPN-данные в сообщении об ошибке.

## Результат операции неизвестен

Blocked означает, что перед безопасным продолжением нужна проверка или восстановление. Изучите исходную операцию вместо повторной переустановки/удаления. Сохраняйте журналы драйвера и ноды. При удалении проверьте указанный оставшийся ресурс и результат независимой проверки хоста.

## Проблемы интерфейса

Для Workstation нужно хотя бы 70 столбцов × 30 строк. Длинные страницы прокручиваются колесом или ползунком. Если копирование недоступно, сохраните файл конфига. Для iOS используйте отправку отдельным сообщением в Telegram.

В сообщение об ошибке включите релиз, ОС/терминал или Telegram-клиент, путь экрана, шаги воспроизведения и журналы без секретов. Отделяйте подтверждённую ошибку от результата, который ещё не проверен.
