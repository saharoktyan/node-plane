# Настройки установки

Настройки контроллера общие для Telegram и Workstation. Оформление и подключения самого Workstation находятся в отдельном разделе **Settings**.

## Installation defaults

В Workstation откройте **Node Plane Settings → Basic → Installation defaults**, в боте — значения установки в настройках администратора.

Выберите протоколы, транспорты Xray и режимы портов. В **Advanced options** находятся SNI, fingerprint, XHTTP path и параметры AWG. В Telegram нажатие на название параметра открывает его редактирование. Auto AWG показывает предпочтительный порт пресета.

Измените значения, проверьте черновик и сохраните. Reset draft отменяет несохранённые изменения. Значения по умолчанию используются для будущих установок; существующий сервер редактируется в его настройках.

## Политики

Сбор трафика включается администратором и собирает поддерживаемую статистику профилей. При наличии данных карточки серверов также показывают месячные суммарные значения. Отключение сбора профилей влияет на пользовательскую статистику; счётчики предназначены для наблюдения, а не принудительного применения квот.

**Requests settings** управляет запросами доступа и автоматическим одобрением. При настройке одобрения проверьте сроки и разрешения: само одобрение аккаунта не определяет все разрешения протоколов. Там же задаются сообщения бота посетителям: **приветствие**, пока запросы включены, и **заглушка**, пока выключены.

## Тексты на нескольких языках

Названия и описания тарифов, рассылки и сообщения посетителям пишутся по языкам — на всех, которые поддерживает текущая версия (сейчас английский и русский). Обязателен только первый написанный текст — исходный. Язык без своего текста показывает исходный или другой уже написанный перевод, выбранный через **Показать другой**, чтобы люди с этим языком всё равно получили сообщение. **Сделать исходным** переносит исходный текст на другой написанный язык. В боте и в Workstation редактор одинаковый; `GET /api/v1/system/languages` возвращает языки, а API принимает такой текст как `{"source": "en", "texts": {...}, "fallback": {"ru": "en"}}`.

## Название бота и SSH-ключ

Отображаемое название бота задаётся в настройках установки → Telegram; как и остальные настройки бота, оно скрыто, пока бот выключен. Публичный SSH-ключ контроллера нужен только для **Установить по SSH** в боте: добавьте его в `authorized_keys` сервера сами. Скопируйте его или отправьте отдельным сообщением из бота. Приватные ключи храните приватно.

## Сервисы

**Админ-панель → Сервисы** в боте и **Settings → Services** в Workstation показывают сервисы установки по видам: системные (relay, веб-кабинет и Telegram-бот), встроенные, к которым люди получают доступ (VPN), и позже — свои сервисы из манифестов. У каждого — состояние и сколько экземпляров работает на нодах. Отсюда открываются страницы relay, веб-кабинета, Telegram и того, где работает бот, «Назад» возвращает сюда. Клиенты берут тот же список из `GET /api/v1/services`; свои сервисы аккаунта — `GET /api/v1/me/services`.

## Relay

Relay — публичный адрес установки: туннель к API контроллера, через который к нему ходят веб-кабинет и другие клиенты. Он работает как сервис на ноде с установленным агентом; контроллер сам подключается к нему и наружу не открыт. Настройте его в боте через **Настройки системы → Relay** или в Workstation через **Settings → Basic → Relay**: выберите ноду, домен кабинета и способ получения TLS (Let's Encrypt на порту 443, файлы сертификата на ноде или обратный прокси перед relay). Тот же экран открывается с ноды: в её настройках relay можно установить на эту ноду, а у ноды с relay на карточке есть **Настройки relay**. «Назад» возвращает туда, откуда вы пришли. Relay один на установку; управляют им владельцы и администраторы. Пока relay раздаёт веб-кабинет или через него работает Telegram-бот на ноде, удалить его нельзя: сначала перестаньте раздавать кабинет или верните бота на контроллер.

Встроенный режим Let's Encrypt использует TLS-ALPN-01: для выпуска и продления сертификата домен должен вести прямо на ноду с доступным портом 443. В Cloudflare оставьте запись в режиме **DNS only** (серое облако): HTTPS-прокси мешает этой проверке. Чтобы сохранить проксирование Cloudflare, используйте файлы сертификата с отдельным выпуском и продлением (например, через DNS-01) или обратный TLS-прокси перед relay. В Cloudflare включите gRPC и используйте Full (strict) с действительным сертификатом сервера. После неудачных проверок Let's Encrypt может ограничить новые попытки: смотрите время повтора в журнале relay, не пересоздавайте сервис многократно.

## Веб-кабинет

Веб-кабинет — приложение, которое открывают в браузере или как Mini App в Telegram. Он входит в выпуск контроллера и обновляется вместе с ним. Где его раздавать, задаётся в боте через **Админ-панель → Сервисы → Веб-кабинет** или **Настройки системы → Веб-кабинет**, в Workstation — **Settings → Basic → Web cabinet** (и в **Services**):

- **На ноде relay**: relay раздаёт его рядом с API на своём домене. Сначала установите relay, дальше — одна кнопка. Контроллер передаёт файлы агенту ноды, тот хранит каждую версию целиком в `/var/lib/node-plane-cabinet/`.
- **С контроллера**: собственный сервер контроллера (юнит `node-plane-cabinet`) раздаёт кабинет без relay и передаёт его запросы к API по правилам relay. Укажите адрес и порт, где слушать (не 8080 — он занят API), и адрес, по которому кабинет открывают, например за вашим обратным прокси. Контроллер тогда слушает сеть: откройте только этот порт.

На странице видны адрес кабинета, откуда он раздаётся, состояние и версия. Чтобы перенести его из одного места в другое, сначала нажмите **Перестать раздавать**. Адрес кабинета — домен passkeys и адрес ссылок-приглашений. Управлять кабинетом через relay нельзя, даже из самого кабинета.

## Рассылки

Выберите получателей, при желании задайте заголовок (одна строка до 120 символов; **Без заголовка** пропускает шаг), напишите сообщение на одном или нескольких языках и проверьте предпросмотр перед отправкой. Заголовок пишется по языкам, как и текст; в Telegram он стоит над сообщением, во входящих — называет его. В API это поле `titles`. Каждый получатель видит текст на своём языке или выбранный для него; предпросмотр показывает, сколько людей читает каждый язык и что именно. После отправки проверьте результат доставки. Получатель может закрыть сообщение и открыть его повторно в Notifications; dismiss удаляет запись из его списка.

Бэкапы, алерты, аудит и очистка описаны в [Обслуживании](maintenance.ru.md).
