# Параметры протоколов

Node Plane поддерживает **VLESS с Xray REALITY** и **AmneziaWG**. Для новых установок задавайте параметры в Installation defaults, для конкретной ноды — в её настройках. Перед применением к работающей ноде проверьте изменения.

При смене общего публичного адреса адреса протоколов, совпадавшие с прежним общим адресом, меняются вместе с ним. Отдельные адреса VLESS/AWG сохраняются. Частичное обновление настроек через API сохраняет пропущенные поля; выбор режима AWG `auto` без порта запускает новый выбор по пресету. На работающей ноде изменения нужно применить перед выдачей новых конфигов; уже скачанные клиентские файлы нужно получить и импортировать заново.

Если после прежнего редактирования в полях адресов VLESS/AWG остался старый адрес, один раз задайте в них текущий общий адрес и примените настройки. Ранее разошедшиеся адреса нельзя отличить от намеренно заданных отдельных endpoint.

## Xray / VLESS

| Параметр | Назначение |
| --- | --- |
| TCP | Транспорт VLESS/REALITY с Vision flow |
| XHTTP | HTTP-транспорт VLESS/REALITY |
| TCP port | TCP-порт транспорта TCP; исходное значение 443 |
| XHTTP port | TCP-порт XHTTP; исходное значение 8443 |
| SNI | TLS-имя сервера, например `www.cloudflare.com` |
| Fingerprint | TLS-fingerprint клиента; исходное значение `chrome` |
| XHTTP path | HTTP-путь; исходное значение `/assets` |

Для SNI используйте корректное имя хоста без схемы, пути и порта. Клиентская ссылка содержит адрес ноды, транспорт и параметры REALITY. После изменения ключей, портов или транспорта получите свежий конфиг.

Отзыв VLESS-идентификатора запрещает новые подключения. Установленные соединения могут работать до отключения.

## AmneziaWG

**Ручной профиль:** Telegram → нода → AWG → Ручные параметры; NPW → редактор ноды → Manual AWG parameters. Вставьте полный блок `параметр = значение`: Jc/Jmin/Jmax, S1–S4, H1–H4, I1–I5, HeaderProtectionKey, RandomTrailers и DisableCookies. ContentPaddingAddition и пять полей таймеров необязательны; без них используются значения движка по умолчанию. На доступной ноде редактор показывает текущие параметры. Серверные и клиентские ключи сюда добавлять не нужно. Backend и агент проверяют всю комбинацию, применение сохраняет идентичности, но требует новых клиентских конфигов. Введите `auto` для возврата к генерации. Отдельная регенерация энтропии недоступна при активном ручном профиле.

AWG использует **UDP**-порт. Auto выбирает порт с учётом I-пресета и доступности; интерфейс показывает предпочтительный порт пресета. Manual использует указанный вами порт. Xray TCP и AWG UDP могут использовать одинаковый номер порта, поскольку работают через разные транспорты.

I1–I5 описывают CPS-последовательности пакетов. В интерфейсе можно выбрать пресет QUIC, DNS или chaos. Для новых профилей независимо генерируются padding пакетов, различные случайные заголовки, ключ защиты заголовков, диапазоны padding содержимого и интервалы handshake/rekey. Cookie-защита остаётся включённой. Параметры используются сервером и его клиентами; пресет не гарантирует подключение через конкретную сеть.

Обновление Node Plane сохраняет существующие профили AWG 3.1, включая профили со стандартными таймерами. Новые значения применяются при инициализации нового интерфейса или явной регенерации энтропии. Регенерация сохраняет ключи идентичности сервера и peers, но меняет общие параметры обфускации: после неё получите и импортируйте свежие клиентские конфиги. Runtime отвергает чрезмерный padding, неположительные интервалы таймеров и интервалы rekey, пересекающиеся со сроком отбрасывания сессии.

Ключ защиты заголовков используется сервером и его клиентами. Экспорт должен сохранять параметры AWG; используйте совместимый клиент и отдельное устройство для каждого клиента.

Доступны WireGuard-подобный `.conf` и форматы Amnezia, где они предлагаются. После изменения протокола или чистой переустановки может потребоваться импорт новых файлов.

## Проверка изменений

1. Проверьте публичный клиентский адрес и доступность TCP/UDP-портов.
2. Сохраните и примените настройки ноды.
3. Проверьте результат операции и состояние runtime.
4. Получите свежий конфиг и протестируйте его из клиентской сети.

Версии контейнеров задаются runtime-ресурсами релиза. Пресет или успешная проверка здоровья не гарантируют подключение через любую сеть.

## IPv6

`Исходящий IPv6` — общая настройка ноды для AmneziaWG и VLESS. По умолчанию включена; также доступна в Installation defaults для будущих нод. Включённая настройка разрешает выход по IPv6, если у хоста есть IPv6-связность. Выключенная отклоняет IPv6 в AWG и ограничивает назначения Xray адресами IPv4. Если IPv6 на сервере недоступен, IPv4 остаётся доступным.

Конфиги полного туннеля AWG включают `0.0.0.0/0` и `::/0` независимо от переключателя. IPv6 клиента попадает в туннель и при выключенном серверном IPv6 outbound. Добавление туннельных IPv6-адресов сохраняет ключи существующих peer. После обновления runtime ноды и применения настроек заново получите и импортируйте конфиги на существующих устройствах: скачанные файлы не обновляются автоматически.

VLESS-ссылка настраивает прокси-соединение, но не системные маршруты устройства. Используйте VPN-клиент с режимом TUN/VPN, который перехватывает IPv4, IPv6 и DNS. При браузерном/системном прокси или TUN только для IPv4 часть трафика устройства может идти мимо Xray; сервер не может изменить эти маршруты через VLESS-ссылку.
