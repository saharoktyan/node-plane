# Параметры протоколов

Node Plane поддерживает **VLESS с Xray REALITY** и **AmneziaWG**. Для новых установок задавайте параметры в Installation defaults, для конкретной ноды — в её настройках. Перед применением к работающей ноде проверьте изменения.

## Xray / VLESS

| Параметр | Назначение |
| --- | --- |
| TCP | Транспорт VLESS/REALITY с Vision flow |
| XHTTP | HTTP-транспорт VLESS/REALITY |
| TCP port | TCP-порт транспорта TCP; исходное значение 443 |
| XHTTP port | TCP-порт XHTTP; исходное значение 8443 |
| SNI | TLS-имя сервера, например `www.cloudflare.com` |
| Fingerprint | TLS-fingerprint клиента; исходное значение `chrome` |
| XHTTP path | HTTP-путь; исходное значение `/assets` |

Для SNI используйте корректное имя хоста без схемы, пути и порта. Клиентская ссылка содержит адрес ноды, транспорт и параметры REALITY. После изменения ключей, портов или транспорта получите свежий конфиг.

Отзыв VLESS-идентификатора запрещает новые подключения. Установленные соединения могут работать до отключения.

## AmneziaWG

AWG использует **UDP**-порт. Auto выбирает порт с учётом I-пресета и доступности; интерфейс показывает предпочтительный порт пресета. Manual использует указанный вами порт. Xray TCP и AWG UDP могут использовать одинаковый номер порта, поскольку работают через разные транспорты.

I1–I5 описывают CPS-последовательности пакетов. Выберите готовый пресет или корректные собственные значения. Advanced options содержат junk-параметры, настройки пакетов и заголовков, padding и интервалы. Используйте сгенерированные значения, если нет причины их менять.

Ключ защиты заголовков используется сервером и его клиентами. Экспорт должен сохранять параметры AWG; используйте совместимый клиент и отдельное устройство для каждого клиента.

Доступны WireGuard-подобный `.conf` и форматы Amnezia, где они предлагаются. После изменения протокола или чистой переустановки может потребоваться импорт новых файлов.

## Проверка изменений

1. Проверьте публичный клиентский адрес и доступность TCP/UDP-портов.
2. Сохраните и примените настройки ноды.
3. Проверьте результат операции и состояние runtime.
4. Получите свежий конфиг и протестируйте его из клиентской сети.

Версии контейнеров задаются runtime-ресурсами релиза. Пресет или успешная проверка здоровья не гарантируют подключение через любую сеть.
