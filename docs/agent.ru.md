# Агент ноды на сервере

Агент — единственный компонент Node Plane на VPN-сервере. Контроллер управляет сервером только через API агента по взаимному TLS. Здесь описано, что делает команда установки, как агент знакомится с контроллером и зачем ему root.

## Требования

- Linux x86_64 с systemd.
- `curl` или `wget`, `tar` и `sha256sum`.
- Debian или Ubuntu для автоматической установки Docker и инструментов ограничения скорости (`iproute2`, `nftables`, `util-linux`).
- Контроллер должен достучаться до порта агента, по умолчанию TCP 50061 (`NODE_AGENT_PORT` на контроллере). Если у провайдера свой файрвол, откройте в нём этот порт. Контроллер подключается к клиентскому адресу ноды.

## Что делает команда установки

**Установка сервера** показывает одноразовую команду, либо **Auto** в Workstation выполняет её по SSH. Команду нужно запускать от root. Она:

1. Скачивает `node-plane-agent-installer.sh` из GitHub-релиза версии контроллера и проверяет его SHA-256. Контроллер не выдаёт команду, если установщик в релизе отличается от его собственной копии.
2. Установщик скачивает архив агента того же релиза, проверяет SHA-256 из команды и устанавливает `/usr/local/bin/node-plane-agent`.
3. Ставит через `apt-get` недостающие инструменты ограничения скорости. Без них нода только сообщает, что не может ограничивать скорость.
4. Записывает `/etc/node-plane/agent.toml` и токен в `/etc/node-plane/tls/enrollment.token`. Прежние ключ и сертификат агента удаляются.
5. Если активен `ufw`, открывает порт агента.
6. Устанавливает и запускает systemd-сервис `node-plane-agent`.

Контроллер не получает ни SSH-доступа, ни SSH-ключа, ни sudo. **Auto** в Workstation входит один раз вашим ключом или паролем, использует `sudo`, если вход не под root, и ничего не сохраняет.

## Регистрация

Агент сам генерирует закрытый ключ на сервере; ключ сервер не покидает. Пока у агента нет сертификата, на его порту работает только регистрация.

Подключается всегда контроллер к агенту, а не наоборот, поэтому контроллер может стоять за NAT. Обе стороны доказывают знание токена через HMAC от данных обмена, включая открытый ключ агента. Сам токен по сети не передаётся, а посредник не может подменить ключ. Затем контроллер выпускает своим CA сертификат на ключ агента. Агент сохраняет CA и сертификат, удаляет токен, применяет правило доступа к порту и переходит на взаимный TLS.

Токен одноразовый и действует час. Контроллер хранит его только до использования или истечения срока, в резервные копии он не попадает. Новая команда заменяет неиспользованную.

Если на сервере был агент другой установки Node Plane, его журналы команд архивируются. Агент, принадлежащий другой активной ноде того же контроллера, отклоняется.

## Доступ к порту агента

Выбирается перед показом команды:

- **Открытый порт** (рекомендуется). Порт доступен всем, но обслуживается только клиент с сертификатом контроллера. Работает и при смене адреса контроллера, например за домашним NAT.
- **Только адрес контроллера**. Правило `ufw` пускает только адрес, с которого контроллер подключился при регистрации. Выбирайте только для статического адреса: после смены контроллер не достучится до агента, пока вы не измените правило на сервере, например `sudo ufw allow 50061/tcp comment 'Node Plane agent'`.

Если `ufw` не активен, агент файрвол не трогает; при необходимости ограничьте порт своим файрволом.

## Зачем агенту root

Агент выполняет на сервере работу, которая требует root:

- запускает контейнеры Xray и AmneziaWG через Docker; доступ к сокету Docker уже равнозначен root;
- ставит Docker и системные пакеты через `apt-get` при установке сервера;
- открывает VPN-порты в `ufw`;
- ограничивает скорость через `tc` и `nft` и входит в сетевое пространство контейнера AmneziaWG через `nsenter`;
- записывает настройку IPv6 в `/etc/sysctl.d/70-node-plane-ipv6.conf`;
- управляет файлами протоколов в `/opt/node-plane-runtime`, `/etc/xray` и `/opt/amnezia/awg`;
- удаляет себя и свои ресурсы при удалении ноды.

Уже из-за Docker отдельный непривилегированный пользователь не ограничил бы возможности взломанного агента. Rootless-контейнеры не поддерживают сетевые возможности ядра, нужные AmneziaWG.

## Что контроллер может делать на сервере

Контроллер вызывает API агента: развёртывание протоколов, доступ профилей, настройки, диагностика, ограничения скорости и подключений, удаление. Изменения журналируются на сервере.

Текущее ограничение: контроллер всё ещё передаёт скрипты, которые агент запускает от root, поэтому взломанный контроллер может выполнить код на своих нодах. Дальше в планах: перенос оставшихся скриптов в агент, подписанное самообновление агента вместо обновления по SSH и systemd-песочница для агента. До подписанного самообновления обновления агента на нодах, установленных командой, с контроллера не доставляются.

## Файлы на сервере

| Путь | Содержимое |
|---|---|
| `/usr/local/bin/node-plane-agent` | Бинарь агента |
| `/etc/systemd/system/node-plane-agent.service` | Сервис |
| `/etc/node-plane/agent.toml` | Ключ ноды, адрес прослушивания, пути TLS |
| `/etc/node-plane/tls/` | Ключ и сертификат агента, CA контроллера; токен до регистрации |
| `/etc/node-plane/node.env` | Настройки ноды |
| `/var/lib/node-plane-agent/` | Журналы команд и идентификатор установки контроллера |
| `/opt/node-plane-runtime/` | Файлы протоколов и клиентские конфиги |

Полное удаление ноды удаляет агент и его ресурсы и проверяет хост. См. [Ноды](nodes.ru.md#удаление-ноды).
