# Node Plane

**Node Plane — open-source control plane для собственной VPN-инфраструктуры.** Он помогает владельцам Linux VPS устанавливать и управлять VLESS/Xray REALITY и AmneziaWG на одном или нескольких серверах. Администраторы используют локальное терминальное приложение Workstation и Telegram-бота, а пользователи получают VPN-конфигурации через Telegram.

**Ранняя публичная бета:** я ищу пользователей, готовых установить Node Plane на тестовый VPS и попробовать его в реальных условиях. Публичные версии `0.x` используют отдельный канал `beta`; экспериментальные alpha-сборки остаются в `dev`. До stable 1.0 состав функций будет уточняться по результатам беты.

## Зачем нужен Node Plane

Для начала достаточно Linux VPS и SSH-доступа. Workstation установит контроллер с вашего компьютера: открывать серверную консоль и выполнять в ней установочные команды не требуется. Один VPS может совмещать контроллер и VPN-протоколы; дополнительные серверы можно подключить позже.

- **Общий путь настройки:** подключитесь к серверу, установите Node Plane и пройдите Quick Start для установки выбранных протоколов.
- **Управление с компьютера и телефона:** серверы, доступ пользователей, обновления, бэкапы и диагностика доступны через Workstation или Telegram.
- **Публичный веб-порт администрирования не нужен:** Workstation подключается через SSH, агенты нод используют mTLS. Это сокращает набор открываемых интерфейсов, но не гарантирует безопасность или отсутствие блокировок IP.
- **Доступ для небольших групп:** создавайте профили, одобряйте запросы, выдавайте доступ к серверам и протоколам, создавайте временные конфигурации и управляйте сроком действия или отзывом доступа.
- **Доставка через Telegram:** пользователи получают файлы конфигурации, ссылки и QR-коды через локализованного бота.

Node Plane подойдёт тем, кто хочет меньше вручную администрировать собственный VPN, особенно если нужно управлять несколькими серверами или делиться доступом с другими. Текущие компромиссы: меньше возможностей управления протоколами, чем у развитых панелей, отсутствие браузерного интерфейса администратора и выдача конфигов пользователям преимущественно через Telegram.

## Тестирование беты

Я уже проверил основные сценарии установки и администрирования. Минимальная просьба для публичной беты простая: установите Node Plane на тестовый VPS и сообщите, что сработало, а что нет. Мне важно понять, как он ведёт себя у разных VPS-провайдеров, на разных ОС, в разных сетях и с разными клиентскими устройствами, а также какие улучшения нужно поставить в приоритет.

Если хотите проверить больше, попробуйте Workstation и Telegram, локальные и удалённые ноды, изменение протоколов, одобрение доступа, истечение срока, заморозку, отзыв, обновления, бэкапы и восстановление. В отчёте укажите ОС, VPS-провайдера, протокол, VPN-клиент и точные шаги воспроизведения, если что-то сломалось или оказалось непонятным. Также напишите, каких возможностей не хватает и что заставило бы вас продолжить или прекратить использование Node Plane. Секреты нужно удалить: не публикуйте токены, приватные ключи, VPN-конфигурации и другие учётные данные. Предпочтительный канал — [GitHub Issues](https://github.com/saharoktyan/node-plane/issues).

В качестве неформальной проверки удобства два человека без какого-либо опыта работы с Linux, начав с двух пустых VPS, примерно за 20 минут прошли полный путь установки и получили по два VPN-сервера на каждом VPS; на них были настроены VLESS TCP, VLESS XHTTP и AmneziaWG. Это единичное наблюдение, а не бенчмарк и не гарантия для любого окружения.

## Быстрый старт

Нужны **Linux VPS x64 с systemd**, привилегированный SSH-доступ, токен Telegram-бота от [@BotFather](https://t.me/BotFather) и ваш числовой Telegram ID. На Debian/Ubuntu Docker устанавливается автоматически. Workstation поддерживает Linux x64, macOS Intel/Apple Silicon и Windows x64.

### Установка Workstation

Выполните команду **на своём компьютере**.

**Linux / macOS**

```sh
curl -fsSL https://raw.githubusercontent.com/saharoktyan/node-plane/beta/scripts/install_workstation.sh | bash -s -- --channel beta
```

Эта команда скачивает shell-скрипт с GitHub и сразу выполняет его. Скрипт небольшой и открыт для просмотра; если вы хотите сначала проверить его, скачайте его отдельно и запустите локальную копию. Bootstrap находит релиз и скачивает установщик Workstation из GitHub Releases по HTTPS. Перед запуском проверьте релиз и поведение установщика по опубликованным файлами проекта; сама команда не заменяет проверку исходника.

**Windows — PowerShell**

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/saharoktyan/node-plane/beta/scripts/install_workstation.ps1'))) -Channel beta
```

Откройте новый терминал и запустите `node-plane-beta`. На Windows также можно открыть **Node Plane (Beta)** через меню «Пуск». Размер терминала — не меньше 70 столбцов × 30 строк. [Сборка из исходников](docs/workstation.ru.md#сборка-из-исходников).

### Первое подключение

1. Создайте профиль установки в Workstation: IP сервера, SSH-порт и пользователь. Подключитесь по паролю или существующему SSH-ключу; проверьте показанный отпечаток ключа сервера.
2. Выберите **Install Node Plane**, укажите токен бота и свой Telegram ID, подтвердите установку.
3. Пройдите **Quick Start**: создайте ноду, выберите протоколы и запустите настройку сервера. Локальная нода использует тот же VPS, SSH-нода — другой сервер.
4. Откройте своего бота, отправьте `/start`, выберите **Получить конфиг** и импортируйте конфигурацию в совместимый VPN-клиент.

Указанный при установке Telegram ID автоматически получает права администратора. Чтобы поделиться доступом, одобрите запрос другого человека или создайте ему профиль и выдайте доступ к серверам. Подробнее: [Профили и доступ](docs/access.ru.md).

## Что уже работает

- Локальные и удалённые VPN-ноды, установка протоколов и настройки серверов.
- Аккаунты, VPN-профили, разрешения на серверы/протоколы, запросы доступа и устройства AWG.
- Выдача файлов конфигураций, ссылок и QR-кодов через Telegram.
- Сроки доступа, заморозка профиля, отзыв доступа и временные конфигурации.
- Статистика трафика, наблюдение за ресурсами серверов, уведомления и оповещения.
- Обновление установки, резервирование/восстановление конфигурации и диагностика/восстановление операций.

VLESS-конфигурации выдаются в виде URI или QR-кодов, а конфигурации AmneziaWG — в виде файлов `.conf`. Используйте VPN-клиент, поддерживающий соответствующий формат; VLESS URI настраивает прокси-соединение, а для маршрутизации всего устройства нужен клиент с режимом TUN/VPN. Я проверял VLESS в v2rayA на Linux, v2rayN на Windows, NekoBox на Android (только TCP-транспорт) и v2box на iOS. AmneziaWG я проверял через AmneziaVPN на Linux, Windows, Android и iOS. Это результаты моих проверок, а не гарантия совместимости с каждой версией и устройством.

Статистика трафика доступна; квоты трафика и ограничения числа подключений пока не реализованы. Отзыв VLESS-доступа запрещает новые подключения, но уже установленные соединения могут продолжать работать до отключения.

## Сравнение с 3x-ui и Remnawave

Сравниваются документированные стандартные сценарии, а не все сторонние интеграции и индивидуальные настройки. Сверено с официальной документацией **30.10.2026**; это сравнение функций, а не сравнительное тестирование безопасности или производительности.

| Возможность | Node Plane сейчас | 3x-ui | Remnawave |
| --- | --- | --- | --- |
| Первоначальная установка | Workstation устанавливает через SSH с вашего компьютера; вручную выполнять команды в консоли VPS не нужно | Установщик/Docker на сервере; есть unattended и cloud-init | Настройка Panel, reverse proxy и Node |
| Публичный веб-порт администрирования | Для стандартного сценария не нужен | Веб-администрирование является частью документированного сценария; его можно ограничить, например привязкой к localhost и SSH-туннелем | Администрирование через браузерные Panel/Node |
| Администрирование | Workstation TUI и Telegram-бот | Веб-панель и Telegram-бот | Веб-панель; Telegram-уведомления и боты из экосистемы |
| Несколько серверов | Один контроллер управляет локальными и удалёнными агентами нод | Главная панель управляет другими экземплярами через API | Panel и Remnawave Nodes |
| Профили и одобрение доступа | Профили, разрешения, запросы и одобрение доступа, сроки, заморозка, отзыв и временные конфигурации | Управление пользователями и клиентами через панель и документированные интеграции | Управление пользователями, трафиком и доступом через экосистему |
| Выдача конфигураций | Файлы, ссылки и QR-коды через Telegram; локализованные сценарии бота | Панель и документированные сценарии бота/интеграций | Панель и интеграции экосистемы |
| Протоколы | VLESS REALITY TCP/XHTTP и AmneziaWG | Более широкий набор, включая AmneziaWG | Управление прокси на базе Xray |
| Подписки на конфигурации | Запланированы | Есть | Есть |
| Квоты трафика пользователя/клиента | Запланированы | Есть | Есть |
| Сроки доступа | Есть; ограничение для действующих VLESS-сессий описано выше | Есть | Есть |

Источники: 3x-ui — [возможности](https://docs.sanaei.dev/docs/), [установка](https://docs.sanaei.dev/docs/guide/installation/), [multi-node](https://docs.sanaei.dev/docs/operations/multi-node/); Remnawave — [настройка](https://docs.rw/overview/quick-start/), [пользователи и лимиты](https://docs.rw/learn-en/users/), [Telegram-интеграции](https://docs.rw/awesome-remnawave/).

Сильные стороны Node Plane — установка с рабочего компьютера, отсутствие обязательного публичного порта администрирования, модель доступа с одобрением, временные конфигурации и выдача через Telegram. У альтернатив уже есть более широкий набор протоколов, подписки и квоты, а также браузерное администрирование. Выбирайте подходящий вариант по нужному сценарию; веб-панель тоже можно сделать приватной — например, 3x-ui описывает [привязку к localhost и SSH-туннель](https://docs.sanaei.dev/docs/guide/update-uninstall/).

## Запланированные VPN-возможности — пока не реализованы

Это приоритеты разработки на период беты, а не обещание включить каждый пункт в stable 1.0. Подробнее в [roadmap](docs/roadmap.md#ближайшие-приоритеты-разработки).

- Обновляемые подписки для более удобного получения конфигураций.
- Квоты трафика.
- Устройства для VLESS, лимит устройств и ограничение одновременных подключений по VLESS-конфигурации устройства.
- Ограничения скорости для профиля.
- Более сильный отзыв активных сессий и ручной конструктор цепочек серверов.

## Требования и документация

Для небольшой совместной установки контроллера и VPN ориентируйтесь на **1 vCPU, 1 ГиБ RAM и 10 ГиБ свободного диска** после ОС, с запасом на трафик, журналы и бэкапы. Это ориентир для планирования, а не гарантия пропускной способности. Контроллер использует PostgreSQL и systemd; стандартная установка запускает PostgreSQL и VPN-протоколы в Docker. Клиентские VPN-порты должны быть доступны.
